# Digua Hackathon — Synthetic Substation Drone Demo

First milestone of the Digua hackathon "substation + drone" track: a watchable
Isaac Sim recording of a quadcopter flying a pre-planned inspection route
through a code-generated substation, with real simulated state feedback and
trajectory/collision evidence.

## Honest scope labels (read first)

| Item | What it is | What it is NOT |
| --- | --- | --- |
| Scene | SYNTHETIC substation generated by code (transformers, gantries, busbars, breakers, CCVTs, fence, corridor, control building) | Not a real site; no real2sim/reconstruction claim |
| Drone | SYNTHETIC quadcopter rigid body (2.0 kg, 0.68 m wheelbase) simulated by PhysX 6-DOF | Not a real airframe model |
| Control | Hand-written cascaded position/attitude PD + rotor mixer, consuming SIMULATED state feedback at 240 Hz | Not autonomous perception, not obstacle avoidance, not a trained policy |
| Route | Pre-planned collision-free waypoints (waypoint tracking demo) | Not exploration/replanning |
| Collision/clearance | PhysX net contact forces + geometric bookkeeping against the known authored layout | Not sensor-based safety evidence |
| Video | 720p30 RealTime render, chase + FPV cameras, one physics run | Not path-traced final quality; not real drone footage |

## Layout

```
examples/digua_hackathon/
  digua_hackathon/
    layout.py       # declarative substation layout + obstacles + waypoints (CPU)
    controller.py   # cascaded PD + mixer (numpy, CPU-testable)
    usd_builder.py  # pxr authoring: substation.usda, quadcopter.usda, stage
    run_demo.py     # Isaac entrypoint: physics + control + dual-cam capture
  tests/            # pure-CPU pytest suite (route clearance is the gate)
  run.sh            # server runner (flock-wrapped GPU modes)
```

## Run (server with the shared Isaac env)

```bash
cd /root/gpufree-data/mingkang/digua-hackathon-drone/simready_infra_pr/examples/digua_hackathon
./run.sh assets runs/demo    # CPU: generate USD assets + manifest
./run.sh smoke  runs/demo    # GPU (flock): 6 s low-res chain validation
./run.sh record runs/demo    # GPU (flock): full mission, 720p dual-camera mp4
```

Outputs land in `runs/demo/`: `run_{mode}.json` (metrics: tracking RMSE,
min clearance, contact events), `trajectory_{mode}.csv` (per-tick reference vs
simulated state), `digua_substation_drone_record_{chase,fpv}.mp4`,
`assets/assets_manifest.json`.

## Tests (CPU, no Isaac)

```bash
cd examples/digua_hackathon && PYTHONPATH=. python -m pytest tests -q
```

Key test: `test_route_clearance_positive_everywhere` — the whole reference
route (and lagged behind-reference positions) must stay clear of every
authored obstacle envelope, so route/asset geometry mistakes fail before any
GPU time is spent.

## Isaac 6.2 gotchas baked into this demo (all hit during development)

- Composed/referenced stage files froze physics-driven rendering (rigid body
  invisible / stuck); the demo assembles the stage **at runtime** instead.
- Fabric-only transforms never reached Hydra in headless base.kit;
  `SimulationManager.enable_fabric(False)` forces USD writeback (`updateToUsd`).
- Collision-only geometry still renders — the envelope box swallowed the drone
  and blacked out the FPV camera inside it; `MakeInvisible()` hides it
  (physics keeps the collider).
- Contact forces need `RigidPrim(..., max_contact_count=N)` plus
  `PhysxContactReportAPI` applied before physics init.
